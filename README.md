# LinkedIn Post Builder

Инструмент для создания постов LinkedIn по фирменным шаблонам. Человек
вводит текст, загружает изображения — всё подставляется в шаблон, и готовую
картинку можно скачать в **PNG** в полном разрешении.

Полностью статичное приложение (HTML + CSS + JS, без сборки и зависимостей) —
работает локально и на любом статическом хостинге.

## Запуск локально

Просто откройте `index.html` в браузере. Либо поднимите локальный сервер
(нужно для корректной загрузки фоновых PNG):

```bash
python3 -m http.server 8000
# затем откройте http://localhost:8000
```

## Как это работает

- `index.html` — разметка (панель ввода + превью).
- `styles.css` — стили интерфейса.
- `templates.js` — **конфиг шаблонов**: размеры, фон, зоны текста и фото.
- `app.js` — движок: рисует шаблон на `<canvas>` и экспортирует PNG.

Рендеринг идёт на `<canvas>` в нативном разрешении (например 1080×1080),
поэтому скачанный PNG — пиксель-в-пиксель, без размытия.

## Подставить ваши реальные шаблоны

1. Положите фоновый PNG в папку `templates/` (например `templates/quote.png`).
2. В `templates.js` у нужного шаблона замените блок `background`:

   ```js
   // было (демо-фон, нарисованный кодом):
   background: { type: "draw", draw(ctx, w, h) { /* ... */ } },

   // стало (ваш реальный фон-картинка):
   background: { type: "image", src: "templates/quote.png" },
   ```

3. Подвиньте координаты зон под ваш дизайн. Все `x, y, w, h` — в пикселях
   относительно холста `width × height` шаблона:
   - `textZones` — где и каким шрифтом/цветом печатается текст;
   - `imageZones` — куда вставляется фото пользователя (`fit: "cover"` или
     `"contain"`, `radius` для скругления).

4. Бренд (название, цвета, шрифты) задаётся в объекте `BRAND` вверху
   `templates.js`. Логотип сейчас текстовый (`drawWordmark`) — его легко
   заменить на загрузку реального лого-PNG по аналогии с фоном.

Демо-шаблоны сделаны на условном бренде «Reforma Health», чтобы сразу было
видно, как всё работает.

## Деплой на GitHub Pages

В репозитории есть workflow `.github/workflows/deploy.yml`, который
автоматически публикует сайт при пуше в основную ветку.

После первого пуша включите Pages: **Settings → Pages → Build and
deployment → Source: GitHub Actions**. Сайт будет доступен по адресу
`https://<owner>.github.io/<repo>/`.
